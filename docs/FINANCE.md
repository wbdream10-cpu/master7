# 财务队列与统一对账

财务工作台帮助总部、租户老板和明确获授权的财务员工处理平台内已有记录。它不会连接银行、创建供应商订单、确认外部付款、修改通道开关或自动出款。普通员工和会员不能查看跨会员财务资料。

## 审核队列

银行转账队列支持 `status`、`member`、`from`、`to` 与 `cursor`。每页最多 50 条；财务视图把 `awaiting_review` 固定排在其他状态之前，再按创建时间和编号倒序。没有日期筛选时会覆盖全部历史，旧待审核记录不会被新记录挤出。会员调用同一路径时始终只返回本人记录。

人工提现队列使用相同筛选概念，每页最多 100 条；后台固定按 `pending_review`、`processing`、其余状态排序。没有日期筛选时同样覆盖全部历史待办。提现 CSV 不接受分页标识，默认最近 31 个 MYT 日期，也可传入成对的 `from`／`to` 与状态、会员筛选；超过 10000 条会要求缩小范围。

所有日期边界按 `Asia/Kuching` 计算，开始日期包含当天 00:00，结束日期包含整天。显式范围最多连续 31 天。游标绑定当前租户、访问身份、筛选条件和排序；更换筛选后重放旧游标会被拒绝。银行单据二进制不会进入列表、汇总或统一 CSV。

## 统一账本对账

`GET /api/v1/finance-reconciliation` 接受 `tenant`、`from` 和 `to`，默认最近 7 个 MYT 日期，最多连续 31 天。它只汇总正式环境 MYR 已提交账本：

- 充值来自 `portal_wallet_journal`，按关联订单的 `vpay`、`gspay_myr`、`bank_transfer` 或 `unknown` 分类。
- 提现来自 `portal_wallet_withdrawal_journal`，只代表平台已登记为付款并产生负数钱包账本的记录。
- `netMovementMinor` 是已入账充值减已付款提现，使用整数分，不使用浮点数。
- 一致性标志核对账本和权威订单／提现记录的租户、会员、环境、币种、金额与状态；发现差异时只报告，不自动改账。

`GET /api/v1/finance-reconciliation/export` 导出同一期间的已提交资金移动，充值为正、提现为负。CSV 最多 10000 条，保护可能触发表格公式的字段，记录导出人、租户、日期和行数；不包含银行名称、户口名字、户口号码、付款链接、原始回调、签名、API Key 或厂家秘密。

## 核对边界

统一对账的来源是本平台账本，没有导入银行账户流水、VPay 或 GSPAY+ 的完整厂家结算单，也没有执行逐笔外部结算匹配。它不能证明银行实际余额、厂家 Settlement Balance、手续费、退款、撤销或外部遗漏订单已经核对完成。

页面与 API 只是读取和导出既有账本，不会启用 VPay、GSPAY+、银行转账或提现，不会发起供应商网络请求，也不会自动增加或扣减余额。真正的日结仍需有权限的财务人员把平台 CSV 与受控银行／厂家报表逐项核对，并记录差异处理。

## 验证

```sh
npm run build
npm run test:bank-deposits
npm run test:withdrawals
npm run test:finance-reconciliation
```

测试使用临时 SQLite／PGlite 和合成资料，不访问银行或供应商，不处理真实资金，也不替代真实 Neon 多连接、备份恢复和生产财务验收。
