# VPay 自动入账与后台核对（待接线）

此变更在已有服务门户中实现充值核验、钱包充值账本和后台记录；尚未接入正式游戏平台的会员与建单流程，尚未部署或开放真实充值。它不代表 `master7.vip` 或 `master7.best` 已接通钱包，也不迁移或覆盖旧会员余额。

## 执行流程

1. 可信服务端使用 `reserveForMember` 创建本地订单，会员及租户从已批准账号的数据库归属取得。金额使用整数分，同一会员请求标识不能换金额、租户、商户或环境。
2. 上游建单接口认证成功后，由可信服务端调用 `bindCreatedOrder` 校验并绑定 VPay 订单号。此操作没有浏览器 API，不能由会员自行提交供应商单号。现有 Deposit 申请登记尚未调用这两步，也不会产生可付款订单。
3. VPay 通知先经过集成网关验证签名，再以独立机器凭据转发到 `/api/v1/payment-callbacks/vpay/payment`。钱包服务不接收浏览器付款跳转作为入账依据。
4. 钱包核对已绑定订单、商户、币种、金额与状态，并使用查询凭据从固定网关地址执行 `ORDER_GET`。只有查单结果也匹配且已付款，才进入入账事务。
5. 同一数据库事务更新订单状态、写入一笔金额相反且总和为零的会员／清算账本记录、记录系统操作。全部提交成功后才向网关返回精确的 `SUCCESS`。并发回调和重试不会重复加钱；事务中途失败回滚并返回可重试错误。
6. 会员查看自己的已核验充值余额与记录；总部及租户老板查看授权租户的记录。普通员工默认无资金记录权限。后台保留本地及 VPay 单号、会员、申请金额、入账金额、核验时间、入账时间和复核记录。

## 数据与对账边界

- 新增版本化迁移 `0003_wallet_deposits.sql`，分别支持 SQLite 与 PostgreSQL。PostgreSQL 表保存在私有 schema，启用 RLS，并撤销浏览器角色直接访问。
- UAT／production 账本分别查询；环境标记只表示本地配置，不证明供应商提供了沙箱。没有旧余额初始化、游戏扣款、提款冻结、退款自动冲正或完整银行结算。
- `GET /api/v1/wallet` 返回当前账号在指定租户、环境的充值账本余额。此余额范围为 `deposit_credits_only`，不能当作已迁入的完整游戏钱包。
- `GET /api/v1/payment-records` 返回最多 100 条分页记录和整个筛选期间的合计。支持环境、租户和最多 31 个 UTC 日筛选。界面中的核验／入账时间按 MYT 显示；筛选日期明确为 UTC。
- `GET /api/v1/payment-records/export` 仅限管理角色，导出选定期间最多 10000 条完整订单记录，超过上限返回错误。导出有审计及表格公式注入防护。
- 汇总基于平台订单与账本，并非已导入 VPay／银行全部结算报表的全量对账结果。供应商收款、费率、结算差异和原系统资金仍须实际核对。
- 金额／币种／订单不符、退款或撤销、会员归属变化进入复核；不会删除历史或直接扣回会员余额。临时查单或入账失败留痕并允许重试。没有公开的改余额、清除复核或手工伪造成功接口。
- 只保存核对所需的白名单字段；不保存原始通知、签名、密钥、银行卡号或供应商错误原文。VPay `sign` 可能含可逆编码的秘密，禁止加入日志或账本。

## 配置与依赖

回调默认关闭。所需变量名（秘密只通过服务密钥管理配置）：

| 名称 | 用途 |
| --- | --- |
| `PORTAL_VPAY_SETTLEMENT_ENABLED` | 只有字面字符串 `true` 才启用接收；默认关闭 |
| `PORTAL_VPAY_TRADER_ID` | 经核对的商户编号 |
| `PORTAL_VPAY_ENVIRONMENT` | 显式选择 `uat` 或 `production` |
| `PORTAL_VPAY_CALLBACK_TOKEN` | 网关转发至钱包的独立秘密，32–1024 字节 |
| `PORTAL_VPAY_QUERY_TOKEN` | 仅用于向网关查单的独立秘密，不得使用管理员密钥 |

网关配套变更在 `platform-samples` 的 `codex/vpay-wallet-query-peer` 分支：新增只读 `/platform/vpay/order-query`，使用 `PLATFORM_QUERY_TOKEN`，不得创建订单、提现或读取商户余额。钱包的查询秘密应与该变量对应。网关 `PLATFORM_CALLBACK_TOKEN` 则与钱包的回调秘密对应。两种秘密用途独立，不能放在浏览器。

固定网关的现有生产部署尚没有上述查询端点；部署配套代码前，新接收器查单会失败并拒绝加钱。需先完成原平台会员／订单映射、实际建单流程、隔离数据库迁移及供应商测试，再配置转发 URL 与秘密并启用对应功能。不要把回调 URL 指向登录页、VPay 商户后台或申请登记接口。
